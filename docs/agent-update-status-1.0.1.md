# Agent update status 1.0.1

## Причина

После обновления сервера с 0.55.5 до 1.0.0 агент мог передавать сохранённый результат предыдущей проверки: источник 0.55.5, `skipped`, `downgrade blocked`. Автоматическая проверка выполняется раз в час, при старте или по команде. Web ошибочно называл любую версию источника доступным обновлением и показывал безопасную блокировку отката как ошибку. Перезапуск обновлял результат, но не исправлял отображение.

## Контракт

API `/api/v1/devices/{id}/agent` добавляет `update_view`, сохраняя исходные поля telemetry. Состояния: `unknown`, `current`, `available`, `source_older`, `error`. `available_version` внутри этого представления заполнен только для более новой версии источника. `source_version` и время проверки описывают последнюю проверку, а не текущий источник без запроса. `server_relation` отдельно различает старый агент, одинаковые версии и агент новее сервера.

Только конкретный исторический результат `skipped / downgrade blocked` с подтверждённой более старой версией источника считается безопасным отказом от отката. Другие ошибки не скрываются. Проверки подписей, checksum и запрет downgrade не изменены.

Web использует общее представление backend. Android получает типизированное представление и вычисляет те же состояния при подключении к старому серверу, без разбора JSON в Compose.

## Порядок обновления

Сначала обновите контейнер сервера до 1.0.1 через Docker/TrueNAS. Перевод `latest` в registry не обновляет уже запущенный контейнер: требуется загрузка образа и пересоздание приложения штатным механизмом TrueNAS. Затем нажмите «Проверить и обновить» у агента. Перезагрузка роутера не требуется. Android APK 1.0.1 обновляется поверх прежнего с тем же сертификатом, versionCode 127.

## Проверки

Регрессии покрывают старый источник, одинаковые версии, новую версию, release candidate, неизвестную версию, агент новее сервера и настоящую ошибку проверки подписи. Браузерный тест отправляет telemetry через API и проверяет API и отображение на desktop/mobile.

Локально прошли 479 PostgreSQL/backend/agent тестов, OpenWrt command harness и browser smoke. Android unit/build и сборка instrumentation APK прошли локально; CI дополнительно проверил эмулятор, включая три новых UI-сценария: актуальный агент, безопасный отказ от отката и настоящая ошибка проверки подписи.

Новый изолированный сервер и агенты 1.0.1 проверены 05.10.2026:

- [Netis NX31](../certification/netis-nx31-v1-0-1.json): 91 pass / 4 not applicable.
- [OpenWrt x86/VirtualBox](../certification/openwrt-x86-v1-0-1.json): 76 pass / 19 not applicable; Wi-Fi PHY и температурных датчиков нет.
- Подписанное обновление 1.0.0 → 1.0.1 выполнено на обоих стендах. Реальные telemetry/API/Web подтверждают актуальную версию и отсутствие ложного обновления/ошибки: [Netis](../certification/evidence/netis-nx31-v1-0-1/agent-update-status.json), [x86](../certification/evidence/openwrt-x86-v1-0-1/agent-update-status.json).
- Сравнены хеши 60 установленных файлов на каждом стенде. Проверены браузерный PTY, resize, переподключение, закрытие, перезагрузка роутера, восстановление сети и агента.
- Отдельное внедрение сбоя на каждом стенде подтвердило повторную доставку одного UUID без повторного исполнения и просроченную команду без исполнения: [Netis](../certification/evidence/netis-nx31-v1-0-1/delivery-faults.json), [x86](../certification/evidence/openwrt-x86-v1-0-1/delivery-faults.json). Связь восстановлена; рабочая БД для тестовых сбоев не использовалась.

Матрица использует два API-запроса с одним idempotency key. Она не заявляет принудительную повторную доставку каждой из 95 команд. Sysupgrade проверен на безопасный отказ, не на реальную прошивку; внешний VPN-трафик не проверялся. Многодневный soak и ручная проверка нового APK на телефоне не заявляются. [Метод прогона](hardware-validation-1.0.md) сохраняется, но отчёты 1.0.0 не выдаются за новый backend.

Runtime-код кандидата: `0feb85bcc02eff377fb82a8a75106878c556fe48`. Fingerprint backend/agent: `e071a3e0fcf47a9614180c083b618f34817ae2252f97bef3ebdfa38c0c8d8e8e`. Решение и привязка результатов: [stable readiness 1.0.1](../certification/stable-readiness-v1.0.1.json).

После проверки сохраняются исходные настройки и рабочий агент 1.0.0. Обновление основного TrueNAS-сервера выполняется владельцем; агенты получат 1.0.1 после обновления источника на сервере. Публикация `latest` сама по себе не меняет запущенный контейнер.

В первом проходе Netis временный bridge не успел появиться в telemetry за 45 секунд при интервале 60 секунд. Backend корректно отклонил VLAN preflight. Runner теперь ждёт 120 секунд и явно отказывает, если bridge не подтверждён. Исходный неуспешный результат сохранён приватно; повтор двух VLAN-команд выполняется на том же кандидате, не переносит результаты старой версии.
