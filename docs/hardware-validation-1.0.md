# Аппаратный прогон 1.0.0

Дата: 05.10.2026. Проверяются изолированный сервер 1.0.0 и агент 1.0.0; рабочая база сервера не используется для внедрения тестовых сбоев. Доверенные SSH-ключи обоих стендов сверены владельцем через консоли.

## Метод

Матрица содержит 95 команд. Для каждой применимой команды отправляются два одинаковых API-запроса с одним idempotency key: они должны вернуть один command UUID. Проверяются завершение в допустимое время и post-condition. Для неприменимых команд сохраняется отсутствие соответствующей capability.

Поле `redelivery=pass` в основной матрице означает проверку API-дедупликации, а `timeout=pass` - завершение в пределах timeout. Они **не означают принудительную повторную доставку и истечение срока для каждой из 95 команд**.

Отдельный `delivery-faults.json` проверяет реальную повторную доставку на каждом роутере: lease уже выполненной команды истекает, тот же UUID доставляется агенту второй раз, а тестовый файл содержит ровно одну запись. Другая команда искусственно просрочена до доставки: статус expired, число доставок нулевое, файл не создан. Затем проверяется восстановление связи.

Отдельные runtime post-conditions подтверждают смену boot ID при перезагрузке, связь и свежую telemetry после перезапуска сети, фактическую остановку/восстановление агента, версии после подписанного обновления/rollback. Web SSH проверяется через настоящий браузер: ввод, вывод, resize, повторное подключение и закрытие PTY.

`installed-runtime.json` содержит хеши 60 установленных файлов, сравненных с точными исходниками кандидата. Финальные исходники аппаратного прогона: commit `02a839063de3c2f8d60e63ba0bda39305f256ab3`. Последующие изменения документации, подписей и evidence не меняют runtime fingerprint.

## Безопасность и границы

- Перед прогоном сохраняется конфигурация каждого стенда; после проверок восстанавливаются исходные настройки и подключение к рабочему серверу.
- Агент остаётся обновлённым до 1.0.0. Это не означает обновления работающего TrueNAS-сервера: его владелец обновляет штатно.
- Sysupgrade проверяется на ожидаемый безопасный отказ, без реальной перепрошивки. Отчёт не подтверждает полный цикл прошивки/boot recovery.
- VPN-команды подтверждают профиль и доступный runtime, но не внешний VPN endpoint и end-to-end трафик через него.
- VM не имеет Wi-Fi PHY и температурных датчиков. Результаты Netis не переносятся на все OpenWrt-модели.
- Многодневный soak не проводился. Его нельзя выводить из количества команд или зелёного CI.
- Проверка телефона [сообщена владельцем](../certification/android-owner-validation-v1.0.0.json); версия установленного APK не записана. Финальный подписанный APK проверяется отдельно при публикации.

## Публичные данные

Сырые результаты и резервные копии остаются локальными. Публичные command evidence сохраняют статусы, длительности, runtime post-conditions и SHA-256 оригинала, но не raw logs, параметры процессов, SSID, адреса или секретные payload. PTY-скриншоты содержат только искусственные маркеры теста и вывод `uname`/`stty`.

Отчёты: [Netis NX31](../certification/netis-nx31-v1-0-0.json), [OpenWrt x86](../certification/openwrt-x86-v1-0-0.json). Решение о выпуске и fingerprint: [stable readiness](../certification/stable-readiness-v1.0.0.json).
