# События, уведомления и автоматизация

Функция появилась в тестовой версии `0.36.0`. Откройте **События** в верхней панели Web UI или **Ещё -> События и автоматизация** в Android.

## Журнал событий

Сервер сохраняет изменения состояния роутера, WAN, клиентов, telemetry и команд. Повтор одного события в коротком интервале увеличивает счётчик, а не создаёт бесконечные копии. Запись можно подтвердить или отложить на час.

По умолчанию события хранятся 90 дней, максимум 2000 записей на роутер:

```env
WRTMONITOR_EVENT_RETENTION_DAYS=90
WRTMONITOR_EVENT_MAX_PER_DEVICE=2000
```

## Уведомления

Правило ограничивается роутером, типами событий и важностью. Поддерживаются тихие часы в UTC и отдельное уведомление о восстановлении.

Каналы:

- `in_app` — журнал Web UI и Android;
- `webhook` — HTTPS POST с JSON события;
- `ntfy` — публикация в topic;
- `smtp` — письмо через SMTP сервера.

По умолчанию webhook и ntfy разрешены только через HTTPS на публичный адрес. Для частного ntfy в доверенной локальной сети нужно явно включить:

```env
WRTMONITOR_NOTIFICATION_ALLOW_PRIVATE_TARGETS=true
```

SMTP настраивается только через окружение. Пароль не сохраняется в PostgreSQL и не возвращается API:

```env
WRTMONITOR_SMTP_HOST=smtp.example.ru
WRTMONITOR_SMTP_PORT=587
WRTMONITOR_SMTP_USERNAME=wrtmonitor@example.ru
WRTMONITOR_SMTP_PASSWORD=replace-me
WRTMONITOR_SMTP_FROM=wrtmonitor@example.ru
WRTMONITOR_SMTP_STARTTLS=true
```

В SMTP-правиле хранится только адрес получателя.

## Автоматизация

Сценарий связывает событие с одной командой существующего типизированного контракта. Перед сохранением сервер проверяет command type и payload. Для первого запуска используйте `dry-run`.

Защита:

- cooldown не даёт сценарию запускаться слишком часто;
- лимит запусков в час останавливает шторм событий;
- idempotency не создаёт две команды для одного события;
- command lifecycle не может запускать новую команду;
- disconnect, Web SSH, shell script, token rotation, sysupgrade apply и factory reset запрещены;
- команды максимального риска требуют отдельного разрешения;
- история показывает `queued` только до ответа агента, затем фактический `success` или `failed`.

Готовые шаблоны создают безопасную диагностику при сбое WAN или высокой нагрузке и обновление интерфейсов при появлении клиента.
