# Обновление и сохранность базы

## Поддерживаемый путь

Сервер использует PostgreSQL и Alembic. При запуске версионированной базы выполняются только недостающие миграции. Штатное обновление не удаляет базу и не требует повторной регистрации роутеров.

CI проверяет обновление с предыдущего опубликованного образа: сохраняет владельца и устройство, запускает новую версию на той же базе и повторяет вход. Отдельно проверяются чистая установка и восстановление резервной копии во временную базу. Это не является обещанием совместимости с любой исторической тестовой сборкой.

Базы без `alembic_version` принимаются только после проверки наличия необходимых таблиц и колонок. Несовместимая старая база должна приводиться к поддерживаемому состоянию отдельно; сервер останавливается с ошибкой, а не пересоздаёт её.

## Перед обновлением

1. Создать серверную резервную копию, сохранить её вне контейнера и проверить восстановление через `backup_cli drill`.
2. Записать текущую версию образа и сохранить настройки развёртывания, включая секреты сервера. Резервная копия БД не заменяет копию этих настроек.
3. Обновить образ с сохранением PostgreSQL volume. Проверить вход, список роутеров и поступление телеметрии.
4. При необходимости отката восстановить проверенную копию и прежний образ. Один только запуск старого образа после миграции не считается безопасным откатом.

## Правила для разработки и 1.x

- Начальная миграция использует неизменяемый `0001_schema.json`, зафиксированный по схеме 0.55.2. Она больше не импортирует текущие модели приложения.
- Уже применённые ревизии и исходный снимок не меняются ради новых полей. Изменения оформляются новой ревизией с проверкой обновления и чистой установки.
- Фиксация снимка не повторяет начальную миграцию на существующей базе и не меняет её данные.
- В стабильной ветке 1.x пересоздание пользовательской базы не является штатным способом обновления. Несовместимое изменение должно быть явно описано до выпуска и иметь проверенный путь сохранения данных.
- До объявления 1.0 нужны успешные проверки установки, обновления с выбранной предыдущей версии и восстановления. Исторические отчёты не подменяют проверку изменённой схемы.
