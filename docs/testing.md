# Тестирование

## Автоматические проверки

GitHub Actions запускает PostgreSQL-тесты backend, E2E жизненного цикла команд и refresh-сессий, Ruff, ShellCheck, тесты OpenWrt agent и Android unit tests. Для релиза собирается и проверяется production-signed APK.

Отдельный deployment acceptance поднимает предыдущий неизменяемый серверный образ, создаёт администратора и роутер, затем запускает новый образ с той же PostgreSQL-базой. После обновления проверяются вход и сохранность устройства. Второй прогон проверяет установку на пустую базу и корректность TrueNAS Compose YAML.

PostgreSQL backup восстанавливается во временную БД; CI проверяет `alembic_version` и таблицу владельца, после чего удаляет тестовую БД.

Перед переводом релиза в `latest` workflow проверяет успешные CI и Security точного коммита тега, обязательные jobs и опубликованные артефакты: семь для 0.x, двенадцать для 1.x. Для 0.x проверяется `certification/beta-readiness-v<версия>.json` или явное исключение владельца. Для 1.x требуется `certification/stable-readiness-v<версия>.json`, лицензия и полный E2E физического роутера с совпадающим runtime fingerprint. Проверяются исходники коммита выпуска, не текущая основная ветка. Исключения 0.55.3/0.55.4 не применяются к stable. В контейнере сверяются версия и commit; перенос выполняется по digest. Исторический отчёт не является новым опросом стенда.

Gate готовности обязателен при сборке тега и продвижении релиза. Полный аппаратный E2E 1.x не выдаётся за многодневный soak. Обычные изменения и pull request могут запускать регрессионные тесты до получения обновлённых аппаратных доказательств. Изменение fingerprint не исправляется простым переписыванием хеша в старом отчёте.

`test_client_profile_commands.py` проверяет оба транспорта, команды отдельным клиентам и Wi-Fi, сохранение персональных настроек и отказ без частичного заполнения очереди. `test_terminal_rendering.py` проверяет реальный xterm с CSP, ANSI-цвета и моноширинный шрифт в обеих темах на desktop/mobile. Это браузерная проверка отображения с имитацией WebSocket, не аппаратный PTY-тест.

Chromium smoke-test авторизуется в Web UI и открывает все разделы роутера на 1440x900 и 390x844. Список роутеров и обзор дополнительно проверяются на 1920x1080, 1366x768, 1024x768 и 768x900. Проверяются HTTP-ошибки, `Internal Server Error`, горизонтальное переполнение, dark/light theme, drawer/sidebar, формы и обмен данными с локальным xterm через WebSocket-брокер и тестовый агент; скриншоты сохраняются в CI-артефакте `web-responsive-smoke`.

## Аппаратный E2E Web-терминала

Runner проверяет полный путь от Chromium до настоящего PTY роутера и обратно. Пароль передаётся только через переменную окружения:

```sh
export WRTMONITOR_E2E_PASSWORD='пароль владельца'
python scripts/terminal_hardware_e2e.py \
  --server https://monitor.example.ru \
  --username admin@example.com \
  --device HomeRouter
```

Успешный запуск создаёт `artifacts/terminal-hardware-e2e/result.json` и `terminal.png`. Тест не считается пройденным, пока xterm не получит уникальный маркер вместе с результатом `uname` из shell OpenWrt.

Runner отправляет Enter отдельным терминальным событием и тем самым проверяет тот же поток клавиатуры, которым пользуется человек в браузере. Отдельно проверяются переход в `connected`, вывод команды и закрытие PTY.

## Ручная регрессия

1. Откройте `/setup` на чистом сервере и создайте администратора.
2. Войдите через Web UI, откройте устройство, проверьте telemetry, Wi-Fi, сеть, историю команд и перезагрузку.
3. В Android укажите сервер, войдите, откройте устройство, переключите все вкладки, отправьте приложение в фон, отключите и верните сеть, проверьте автоматическое восстановление событий, refresh истёкшего токена, «О приложении», выход и повторный вход.
4. На OpenWrt выполните `wrtmonitor-agent debug`, `wrtmonitor-agent debug-telemetry` и `wrtmonitor-agent send-now`.
5. Проверьте `/health` и `/health/config` через внешний HTTPS-адрес сервера.
6. После истечения access token убедитесь, что Android обновил сессию без повторного ввода пароля, а повторное использование старого refresh-token возвращает `401`.
7. Создайте PostgreSQL backup и выполните `python -m backend.app.backup_cli drill <файл>`.
8. Оборвите Web SSH закрытием вкладки, убедитесь, что прежняя PTY закрыта, затем откройте терминал снова и проверьте новый session ID и вывод команды.

Полный аппаратный прогон 95 команд выполняется отдельным runner. Порядок запуска,
требования к recovery-доступу и опубликованные отчёты описаны в
[real-router-testing.md](real-router-testing.md).

## Релизные артефакты

Для 1.x публикуются TrueNAS YAML, архив агента, Android APK, LICENSE и `RELEASE_INVENTORY.json` с commit и digest контейнера. Эти файлы и метаданные агента покрывает `RELEASE_SHA256SUMS.txt` с отдельными Ed25519/RSA подписями. После проверки подписей выполнить `sha256sum --check RELEASE_SHA256SUMS.txt`. Ключи брать из заранее доверенного checkout. [Полная инструкция](release-checklist-1.0.md#проверка-файлов-при-выпуске).

`SHA256SUMS.txt` и его подписи описывают только файлы внутри agent archive. Проверка этого манифеста не подтверждает APK или контейнер.
