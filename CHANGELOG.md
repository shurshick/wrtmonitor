# Changelog

## v0.44.0

- Добавлены готовые режимы клиента: без ограничений, ребёнок, гость и IoT.
- Web UI и Android получают режимы и варианты скорости из единого серверного каталога.
- Числовой ввод Кбит/с заменён выбором понятных значений в Мбит/с.
- В карточке показана фактическая текущая скорость, вычисленная по двум реальным точкам `nlbwmon`.
- Добавлены быстрые действия блокировки интернета и закрепления текущего IPv4.
- Сервер определяет активный готовый режим по фактически сохранённой политике без нового поля в БД.
- Расписание клиента теперь действительно задаёт окно разрешённого доступа;
  сервер отвергает пустые дни, пустые часы и одинаковые границы.
- Android `versionCode` повышен до `101`.

## v0.43.0

- Клиентская политика получила проверяемый lifecycle `applying / applied / error` во всех интерфейсах.
- Результат считается успешным только после read-after-write и точного совпадения наблюдаемой политики.
- Реализованы индивидуальные ограничения upload/download по MAC через `tc flower + police`.
- Агент сохраняет лимиты в UCI и восстанавливает runtime-фильтры после запуска.
- Добавлена capability `clients.shaping`; неподдерживаемые поля скрываются в Web UI и Android.
- Installer и updater автоматически устанавливают `tc-full` и необходимые kernel-модули.
- Точные post-condition проверки добавлены для клиентской блокировки и постоянного DHCP-адреса.
- TrueNAS deployment возвращён на образ `latest`; Android `versionCode` повышен до `100`.

## v0.42.0

- Добавлена атомарная операция `configure`: данные карточки клиента и команда применения политики фиксируются одной транзакцией.
- Android загружает детальную карточку выбранного устройства, до 50 событий присутствия и 96 интервалов RX/TX.
- Web UI, Android и API получили окончательное удаление записи клиента и её локальной истории.
- Перед удалением явно указано, что активное устройство появится снова после следующего наблюдения.
- Android `versionCode` повышен до `99`.

## v0.41.0

- Добавлены автоматическое определение типа устройства и ручная корректировка, которую telemetry больше не перезаписывает.
- Для каждого клиента сохраняется ограниченная история переходов `online`, `recent` и `offline`.
- Web UI и Android получили одинаковые типы устройств, детальную историю присутствия и компактные обозначения.
- API дополнен детальной карточкой клиента, отдельной историей активности и приращениями RX/TX между точками трафика.
- Android `versionCode` повышен до `98`.

## v0.30.1-agent-stability

- Агент при запуске возобновляет свежие проверки конфигурации и откатывает
  просроченные транзакции, оставшиеся в `prepared` или `verifying` после сбоя.
- Ограничено время синхронных операций с init-сервисами OpenWrt: зависший
  `dnsmasq` больше не блокирует цикл агента и получение следующих команд.
- DNS-команды возвращают конкретную ошибку перезапуска, а rollback использует
  те же ограниченные по времени сервисные операции.
- Убран конкурирующий полный сбор telemetry сразу после команды; read-after-write
  выполняет post-condition, а telemetry отправляется штатным циклом агента.
- `network.set_lan` распознаёт совпадающую конфигурацию как безопасный no-op,
  перезапускает только LAN-интерфейс и проверяет его фактический IPv4-адрес.
- Исправлена область переменных UCI-verifier, из-за которой корректная LAN-команда
  могла сравниваться с посторонним значением и ошибочно запускать rollback.
- Команды с исчерпанным числом доставок завершаются явной ошибкой, а не остаются
  бесконечно в очереди.
- Секретные поля рекурсивно удаляются из telemetry до сохранения и обработки.
